# Pflichten-Kompass – Hinweise für die Arbeit am Projekt

- Portfolio-Projekt von Robin (Wirtschaftsinformatik, olbricht-digital). Repo `edgebird-lab/pflichtenkompass` ist **seit dem 11.11.2026 öffentlich** (Robins Entscheidung): Jeder Commit ist sofort für alle sichtbar, also keine Zugangsdaten, keine persönlichen Daten, keine fremden Texte (Kammern, Verlage). Keine offene Lizenz: alle Rechte vorbehalten, Programme kostenlos nutzbar (README, Abschnitt „Rechte“). Keine GitHub Pages.
- Releases: Tag `vX.Y.Z` gleich der Version in `package.json` und `src-tauri/Cargo.toml` (und `src/version.ts`), dazu Notizen in `.github/release-notizen/vX.Y.Z.md`; `release.yml` legt einen Entwurf mit dem Installer und seiner Kopie `Pflichten-Kompass-Setup.exe` an. Prüfen, dann `gh release edit vX.Y.Z --draft=false --latest`. Die Website olbricht-digital.de verlinkt fest `https://github.com/edgebird-lab/pflichtenkompass/releases/latest/download/Pflichten-Kompass-Setup.exe`: den Asset-Namen nie ändern.
- Spezifikation: `docs/spezifikation.md` (lang, in Teilen lesen). Fortschritt mit Häkchen: `docs/stand.md`, nach jedem Schritt abhaken. Annahmen und Abweichungen: `docs/entscheidungen.md`.
- Sprache: Oberfläche, Fachbegriffe im Code, Doku und Commit-Nachrichten auf Deutsch. Keine KI-Funktionen, keine Daten außer Haus.
- Rechtsinhalte nur aus dem geprüften Kernkatalog der Spezifikation (6.6, 6.7); keine Pflichten, Fristen oder Paragraphen erfinden. Jede Pflicht mit Rechtsgrundlage, Quelle und Stand; der Hinweis „keine Rechtsberatung“ ist überall sichtbar.
- Fachlogik in `src/modell`, `src/katalog`, `src/regeln`, `src/fristen`, `src/export` ohne React und mit Tests (Werte von Hand nachgerechnet); Oberfläche in `src/ui`. `heute` wird immer übergeben, nie in der Fachlogik gelesen.
- `docs/katalog.md` und `docs/fragenkatalog.md` sind aus `src/katalog/` und `src/modell/fragen.ts` erzeugt: nach jeder Änderung `npm run doku`. Ein Test prüft, dass sie aktuell sind.
- Regeln stehen nur in `regeln/pflichten.dmn` (DMN 1.3, bearbeitbar mit dem Camunda Modeler oder demo.bpmn.io). Nach jeder Änderung `KATALOG_VERSION` und `KATALOG_STAND` in `src/katalog/typen.ts` anheben und `npm run regeln:stand -- --version … --stand …` ausführen; sonst scheitert der Test V12. Der Lader prüft V1–V11 und bricht bei jedem Befund ab.
- Vor jedem Commit: `npm run lint`, `npm test`, `npm run build`, `npm run e2e` (lokal mit Edge). Ports: Vorschau und Browsertests 4182 mit `strictPort`, Dev-Server 5182; nie 4173 (Prozesslotse).
- Keinen Vorschau-Server auf 4182 laufen lassen, wenn die Browsertests starten: `reuseExistingServer` nimmt ihn sonst samt altem Build. Ein im Hintergrund gestartetes `npx vite preview` überlebt unter Windows das Beenden der Shell; vor den Tests `netstat -ano | grep :4182` prüfen und den eigenen Prozess beenden. Browsertests mit Datum nutzen `e2e/hilfen.ts` (`oeffne` setzt „heute“ per `page.clock` auf den 11.11.2026).
- Laufen auf dem Rechner mehrere Apps gleichzeitig, scheitern Browsertests an Zeitlimits (30 s), ohne dass die App fehlerhaft ist; dann `npm run e2e -- --workers=4`.
- Oberfläche: Zustand als Reducer in `src/zustand.ts`, Antworten nur über `setzeAntwort` (abhängige Standardwerte aus 5.2). dmn-js lädt nur in der Regelansicht (`src/ui/RegelAnsicht.tsx`), das Regelwerk per dynamischem Import; beides gehört nicht ins Hauptbundle (Browsertest prüft das). Das bpmn.io-Wasserzeichen nie verdecken.
- Bilder für die README: `node scripts/readme-bilder.mjs` gegen die laufende Vorschau; Rundgang mit `node scripts/ansehen.mjs <ordner>`.
- Windows-Programm: Tauri 2 in `src-tauri` (Kennung `de.olbricht-digital.pflichtenkompass`, Aufbau wie beim Prozesslotsen). Rust liegt in `%USERPROFILE%\.cargo\bin` (im Bash-Tool `export PATH="$USERPROFILE/.cargo/bin:$PATH"`); bauen mit `CARGO_TARGET_DIR=C:/Users/Robin/AppData/Local/cargo-ziel` (gemeinsam mit anderen Apps, cargo wartet bei Sperre; nicht den Ordner des Prozesslotsen). Bei Änderungen an `src-tauri` oder `src/plattform` zusätzlich `cargo test --manifest-path src-tauri/Cargo.toml` und `npm run desktop:test` (vorher `npx tauri build --debug --no-bundle`; Port 9334). Der Desktop-Test bricht ab, wenn der Pflichten-Kompass läuft, und sichert die Programmdaten vorher. Installer nur auf Robins ausdrücklichen Wunsch auf seinem Rechner ausführen (am 11.11.2026 gewünscht: installiert pro Benutzer mit Desktop-Verknüpfung); Testläufe mit `desktop:test`. `src-tauri/windows/installer-test.ps1` deinstalliert am Ende und läuft nur in der CI. Sicherheitsregeln (CSP, Rechte, Erlaubnisliste der Links) prüft `src/plattform/tauri.test.ts`.
